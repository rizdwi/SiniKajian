# QA Audit — SiniKajian / Majelisku

**Tanggal:** 19 Oktober 2026
**Repo:** `rizdwi/SiniKajian` (Laravel 13) — live `https://majelisku.web.id` (Vercel)
**Metode:** baca langsung tiap file kunci + grep pola hardcoded (`example.com`, email, IP, secret literal, TODO, `dd(`, `console.log`, `localhost`) di `app/`, `resources/views/`, `routes/`, `config/`, `public/`, `tests/`
**Aturan:** tidak mengubah kode; nilai secret mentah tidak ditulis ulang (ditandai `[REDACTED]`)

Tiga temuan paling kritis:
1. **`SupabaseUserService::update()` menimpa SEMUA baris `app_users`** — argumen filter ID ke-3 pada `Http::patch()` diam-diam dibuang Laravel, sehingga PATCH tanpa filter dijalankan. Setiap update profil menimpa nama/email/avatar seluruh user di Supabase.
2. **Bookmark & kehadiran 404 di production** — `toggleBookmark()` / `logAttendance()` memakai route-model-binding `Kajian $kajian` ke SQLite lokal yang kosong di Vercel; ID kajian dari Supabase tidak pernah ditemukan lokal.
3. **OAuth tanpa `state` + tanpa cek `email_verified`** — login Google rentan CSRF dan pengaitan akun tanpa verifikasi email.

## CRITICAL

### C-1. `SupabaseUserService::update()` — PATCH tanpa filter, menimpa semua user
- **File:** `app/Services/SupabaseUserService.php:111`
- **Kode:**
  ```php
  ->patch("{$this->url}/rest/v1/app_users", array_merge($data, [
      'updated_at' => now()->toIso8601String(),
  ]), [
      'id' => 'eq.' . $id,   // <-- argumen ke-3
  ]);
  ```
- **Masalah:** signature Laravel `PendingRequest::patch(string $url, array $data = [])` hanya menerima 2 parameter. Argumen ke-3 (`['id' => 'eq.'.$id]`) **diam-diam diabaikan PHP** — filter tidak pernah terkirim. PostgREST menerima `PATCH /rest/v1/app_users` tanpa filter → **mengupdate SELURUH baris tabel**.
- **Dampak:** dipanggil dari `AuthController::updateProfile()` — setiap kali seorang user update profil, nama/email/avatar **semua user** di Supabase tertimpa data user tersebut. Sangat mungkin ini akar kebingungan identitas profil ("OAuth User Test" muncul di akun lain).
- **Fix:** pindahkan filter ke query string URL: `->patch("{$this->url}/rest/v1/app_users?id=eq.{$id}", $data)`.

### C-2. Bookmark & kehadiran selalu 404 di production (route model binding ke SQLite kosong)
- **File:** `app/Http/Controllers/KajianController.php` — `toggleBookmark(Request $request, Kajian $kajian)`, `logAttendance(Request $request, Kajian $kajian)`; route `routes/web.php` (`/kajian/{kajian}/bookmark`, `/kajian/{kajian}/kehadiran`)
- **Masalah:** implicit binding `Kajian $kajian` query ke SQLite lokal. Di Vercel SQLite ephemeral & kosong, sedangkan ID kajian berasal dari Supabase → binding gagal → **404 untuk setiap toggle bookmark/kehadiran di production**.
- **Fix:** ganti parameter jadi `$id` mentah (seperti `show($id)`), validasi eksistensi via `SupabaseKajianService::find()`.

## HIGH

### H-1. OAuth Google tanpa `state`, tanpa cek `email_verified`
- **File:** `app/Http/Controllers/SocialAuthController.php:29-36`, `callback():52-130`
- **Masalah:**
  - `redirect()` tidak mengirim parameter `state` dan `callback()` tidak memvalidasinya → **CSRF pada alur login** (attacker bisa memaksa korban login ke akun attacker).
  - `callback()` tidak memeriksa `$socialUser['email_verified']` dari Google sebelum membuat/mengaitkan akun → akun dibuat untuk email yang belum terverifikasi.
  - `$socialUser['sub']` (Google) / `$socialUser['id']` (FB) diakses tanpa `isset` → error 500 bila respons provider malformed; `$providerId` null bisa membuat `where('provider_id', null)` mencocokkan baris yang salah.
- **Fix:** generate & validasi `state` via session; tolak bila `email_verified !== true`; guard `isset()` untuk field provider.

### H-2. `ResendTransport` menonaktifkan verifikasi TLS di Windows
- **File:** `app/Mail/ResendTransport.php`
- **Kode:**
  ```php
  } elseif (PHP_OS_FAMILY === 'Windows') {
      $options['verify'] = false;
  }
  ```
- **Masalah:** `verify=false` mematikan validasi sertifikat TLS → rentan MITM saat memanggil Resend API (API key + isi email bisa disadap).
- **Fix:** hapus cabang ini; selalu verifikasi TLS (gunakan CA bundle bawaan).

### H-3. ResendTransport me-log isi email lengkap (termasuk token reset) saat API key kosong
- **File:** `app/Mail/ResendTransport.php`
- **Kode:** `Log::warning('ResendTransport: RESEND_API_KEY belum disetel. Email dicatat di log.', $payload);`
- **Masalah:** `$payload` berisi `subject`, `html`, `text` email — termasuk **tautan/token reset password** — tertulis plaintext ke log.
- **Fix:** log hanya metadata (penerima, subject), jangan body.

### H-4. Panel admin rusak di production + sync Supabase tidak pernah jalan
- **File:** `app/Http/Controllers/AdminController.php:20-42`, `verify():64`, `destroy():95`
- **Masalah:**
  - `index()` membaca model `Kajian` lokal (SQLite kosong di Vercel) → panel moderasi kosong/rusak di production.
  - `verify()`/`destroy()` memakai `config('services.supabase.service_role_key')` — key ini **tidak ada** di `config/services.php` (yang ada hanya `service_key`) → selalu null → blok sync Supabase **tidak pernah dieksekusi**. Verifikasi/hapus kajian dari panel admin tidak tersinkron ke Supabase.
- **Fix:** baca kajian via `SupabaseKajianService`; samakan nama config key.

### H-5. `PushController::send()` menghapus subscription valid pada failure sementara
- **File:** `app/Http/Controllers/PushController.php:83-87`
- **Masalah:** komentar menyebut hapus bila "410 Gone", tapi kode menghapus subscription pada **semua** kegagalan (`else { $failed++; $svc->deletePushSubscription(...); }`) → subscription valid terhapus saat error jaringan sementara.
- **Fix:** hapus hanya bila respons 410/404 eksplisit.

### H-6. Atribut `#[Fillable]` User memuat `role` (risiko mass assignment)
- **File:** `app/Models/User.php:18` — `#[Fillable(['name','email','password','provider','provider_id','avatar','role'])]` vs properti `$fillable` baris 21 yang **tidak** memuat `role`.
- **Masalah:** di Laravel 11+ atribut `#[Fillable]` meng-override properti → `role` menjadi mass-assignable. Saat ini belum ada alur yang mengeksploitasi (controller memakai field eksplisit), tapi ini bom waktu privilege escalation bila ada `User::create($request->all())` di masa depan.
- **Fix:** hapus `'role'` dari atribut, atau hapus duplikasi atribut vs properti.

## MEDIUM

### M-1. Email admin hardcoded di dua tempat
- `app/Models/User.php:25` — `strtolower($this->email ?? '') === 'rizkidwisandy@gmail.com'` di `isAdmin()`
- `resources/views/auth/profile.blade.php:256` — `$ownerEmail = 'rizkidwisandy@gmail.com';` (mailto bantuan)
- **Fix:** pindah ke `config('app.admin_email')` / env `ADMIN_EMAIL`.

### M-2. URL project Supabase hardcoded sebagai default
- `config/services.php` — `'url' => env('SUPABASE_URL', 'https://hhcopgprjdjvgfcuqdyf.supabase.co')`
- `app/Console/Commands/PushKajianToSupabase.php:17` — fallback literal yang sama
- **Fix:** default `null`; gagalkan dengan pesan jelas bila env kosong.

### M-3. Path mesin developer bocor ke production
- `app/Mail/ResendTransport.php` — literal `C:/Users/Rizz/AppData/Local/Python/.../cacert.pem`
- **Masalah:** membocorkan username & struktur mesin dev; path tidak akan pernah ada di server.
- **Fix:** hapus cabang ini.

### M-4. `upsertPushSubscription()` — request pertama buggy, request ganda
- **File:** `app/Services/SupabaseUserService.php` (`upsertPushSubscription`)
- **Masalah:** POST pertama menggabungkan `'_upsert' => true` ke body JSON (kolom fiktif → kemungkinan 400), lalu langsung POST kedua dengan header `Prefer: resolution=merge-duplicates`. Dua request untuk satu operasi; yang pertama dead/buggy.
- **Fix:** hapus POST pertama, pertahankan yang ber-`Prefer`.

### M-5. Kajian batal tetap tampil — `is_cancelled` tidak difilter
- **File:** `app/Services/SupabaseKajianService.php` (`getActiveKajians`)
- **Masalah:** cron cancel-monitor menandai `is_cancelled=true`, tapi query frontend tidak memfilternya dan badge "DIBATALKAN" belum ada.
- **Fix:** tambah `'is_cancelled' => 'eq.false'` (atau `is.false`) + badge di Blade.

### M-6. ID user lokal dipakai sebagai `user_id` Supabase
- **File:** `PushController::subscribe()` (`Auth::id()`), `KajianController::toggleBookmark()`, `logAttendance()`, `show()`, `syncBookmarks()`
- **Masalah:** `Auth::id()` adalah ID SQLite lokal (berubah tiap restart Vercel), sedangkan tabel Supabase (`bookmarks`, `attendances`, `push_subscriptions`, `majelis_follows`) memakai ID `app_users` Supabase → bookmark/kehadiran terfragmentasi per sesi, tidak sinkron antar perangkat.
- **Fix:** resolve Supabase user ID via `SupabaseUserService::findByEmail()` sekali per request, pakai itu untuk semua tulis/baca Supabase.

### M-7. `store()` mendorong ID autoincrement lokal ke Supabase
- **File:** `app/Http/Controllers/KajianController.php` (`store`)
- **Masalah:** `'id' => $kajian->id` di-POST ke Supabase → risiko tabrakan primary key dengan sequence Supabase.
- **Fix:** jangan kirim `id`; biarkan Supabase generate, lalu simpan pemetaan bila perlu.

### M-8. Validasi `unique:users,email` hanya cek SQLite ephemeral
- **File:** `app/Http/Controllers/AuthController.php` (`register`)
- **Masalah:** di Vercel, tabel `users` lokal kosong setiap cold start → email duplikat lolos dan membuat baris ganda di Supabase.
- **Fix:** cek duplikat via `SupabaseUserService::findByEmail()` sebelum create.

### M-9. `logout()` tanpa invalidasi sesi & regenerasi token CSRF
- **File:** `app/Http/Controllers/AuthController.php` (`logout`)
- **Masalah:** hanya `Auth::logout()` + `session()->flush()`; best practice: `$request->session()->invalidate()` + `$request->session()->regenerateToken()`.
- **Fix:** tambah kedua panggilan tersebut.

### M-10. Sync kajian tanpa pengaman hasil kosong
- **File:** `app/Console/Commands/SyncKajianFromSupabase.php` — `DB::table('kajians')->whereNotIn('id', $ids)->delete();`
- **Masalah:** bila API Supabase sukses tapi mengembalikan array kosong (gangguan), **seluruh tabel lokal terhapus**.
- **Fix:** abort bila `$rows` kosong / respons tidak valid.

### M-11. Fallback kota hardcoded "Bandung"
- `resources/views/kajian/index.blade.php:829` — `${... : 'Bandung'}` (ini sumber keluhan "Bandung, Jawa Barat" hardcoded)
- `resources/views/kajian/qibla.blade.php:561` — `|| 'Bandung'`
- **Fix:** fallback ke string kosong / "Lokasi belum dipilih".

### M-12. Cabang Facebook OAuth mati tapi tetap ada
- **File:** `app/Http/Controllers/SocialAuthController.php:39-50, 68-83`
- **Masalah:** user memutuskan "Facebook gausah" (permanen), tapi kode, route, dan `config/services.php['facebook']` tetap ada → permukaan serangan & kebingungan.
- **Fix:** hapus cabang facebook + config + dokumentasikan.

## Catatan Keamanan Positif (tidak perlu diubah)

- Tidak ada secret mentah di kode; semua kredensial via env/Vercel.
- Turnstile di login & register; honeypot `website_trap`; rate limiting berlapis.
- `strip_tags()` pada input pengajuan kajian; CSRF token ada di semua form; password policy `Password::min(8)->numbers()->symbols()`.
- Token reset di-hash (`Hash::make`) sebelum disimpan; verifikasi pakai `Hash::check`.
- Tidak ada SQL injection (semua via Eloquent/query builder dengan binding).
